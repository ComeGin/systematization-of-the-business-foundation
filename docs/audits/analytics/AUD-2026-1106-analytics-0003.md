# 観測の補足

Mautic に存在するフォームは `form_id=1`（alias `consult`）のみ（`form_id=2` は Not found で存在しないことを確認した）。`mautic_list_form_submissions` で取得した全送信は 7 件（全期間）のうち、期間内（2026-09-30〜2026-11-03 JST。`dateSubmitted` を JST に換算して判定）は 5 件、期間外（2026-11-04 JST）は 2 件で除外した。

畳み込み（`mautic_form_id` + `lower(email)` + 送信日〈JST〉）の結果も 5 件（いずれも `(form_id, email, 送信日)` の組が異なるため重複なし）。`CV-dedup-dropped` は 0 件であり、二重送信が常態化している徴候は無い。

`CVR-total` は GA4（`docs/audits/analytics/AUD-2026-1106-analytics-0001.md`、`SESSION-count=20`、`fetch.outcome: ok`）と本ファイル（`fetch.outcome: ok`）の両方が条件を満たす（`SESSION-count ≥ 1`、`fetch.range` が同一）ため計算した: `CV-count(5) ÷ SESSION-count(20) = 0.25`。

**CVR-total を読むときの注意**:
- 分母（GA4 のセッション）は Cookie に同意した訪問者だけ、分子（Mautic のフォーム送信）は全員。同意率が下がると CVR は見かけ上上がる。同意率（consent-api の記録）で補正する方法は未決定（ADR-25、DA-02）
- フォームの `umami_session_id` は廃止され、代わりの識別子を足していないため訪問者単位の突合はできない。この `CVR-total` は集計値どうしの比である
- GA4 側の `SESSION-count=20` はプロパティ・ウェブストリームが観測期間終盤（2026-11-01〜02）に作成されたばかりの立ち上げ期間の値であるため、この `CVR-total` も定常的な CVR の参考にはならない
