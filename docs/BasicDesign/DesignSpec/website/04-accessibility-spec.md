# 04. アクセシビリティ仕様（JIS X 8341-3:2016 AA）

公開サイト `frontend/verdant-virgo` を JIS X 8341-3:2016 のレベル AA を目標に試験し、対応度（**一部準拠**。2026-10-19 に決定）と試験結果を公開するための仕様。自社で作る部分は AA の全基準を満たすことを目標にし、満たせないのは第三者のコンテンツ（Chatwoot・Cal.com）だけにする。達成基準ごとに、このサイトのどの部品・ページが該当し、どう満たし、どう試験するかを決める。

- 作成: 2026-10-18（spec-writer）。計画は `docs/superpowers/plans/2026-10-18-jis-x-8341-3-accessibility.md`（以下「計画」）。ユーザーの決定 U-1〜U-5 と、計画の側の決定 P-1〜P-10 はこの文書の前提であり、ここでは覆さない。
- 達成基準の一覧の出典: ウェブアクセシビリティ基盤委員会（WAIC）「JIS X 8341-3:2016 達成基準 早見表（レベル A & AA）」2018年12月版（`docs/data/JIS X 8341-32016 達成基準 早見表(レベルA & AA).pdf`）。原典は JIS X 8341-3:2016（WCAG 2.0 と一致規格）。
- **状態: G-1 承認済み（2026-10-18）。** 文言（§1 の表明の文、§5 の様式の列見出し）は `01-content-spec.md` が正本。G-2（スクリーンリーダーの確認と第三者の埋め込みの扱い）が残る。

**部分適合と「準拠」の関係**（2026-10-18 に spec-writer が出典を読んで確かめた）

- **JIS X 8341-3:2016 の 5.3「部分適合に関する記述－第三者によるコンテンツ」**（WCAG 2.0 の「部分適合に関する記述 － 第三者によるコンテンツ」と同じ内容。JIS X 8341-3:2016 は WCAG 2.0 の一致規格）は、制御できないコンテンツのために適合していないページについて、「このページは適合していないが、制御されていない情報源に起因する以下の部分を除けば、レベル X で適合していることになる」という形の記述を認める。条件は 2 つ: ① その部分をコンテンツ制作者が制御できない、② 利用者が識別できるように記載する（「私たちが制御できない部分すべて」のような書き方はできない）。**この記述をしたページは「適合している」ことにはならない**（記述そのものが「適合していない」と言っている）。出典: WAIC「WCAG 2.1 日本語訳」の 5.4（https://waic.jp/translations/WCAG21/ 。2.0 と同じ文の 2.1 版。**JIS の本文〈有料〉そのものはこのセッションでは読んでいない**）。
- **WAIC の対応度表記ガイドライン（2021年4月版）の 3.2 は、「5.3 部分適合に関する記述－第三者によるコンテンツ」〈と 5.4 言語〉で定められた部分適合を適用するページが存在する場合は、部分適合に関する記述を行った上で「一部準拠」と表記するものとする、と定めている。** 「一部準拠」には、今後の対応方針（必須）と部分適合に関する記述が要り、試験結果の公開は任意。**レベル AA に一部準拠と表記するには、レベル A に準拠していることが前提**。出典: https://waic.jp/docs/jis2016/compliance-guidelines/202104/ 。
- **したがって、第三者のコンテンツを除いて「準拠」と表記することはできない**（WAIC のガイドラインに従って表記する限り）。「準拠」を保つ道は、(b) 埋め込みを外して代わりの手段だけにする（G-2 で選ばれなかった）か、第三者のコンテンツの不足を監視して 2 営業日以内に直す（WCAG の 5.4 の 1 つ目の方法。こちらで直せないので当てはまらない）しかない。
- **未確認の点**: Chatwoot の不足（4.1.2。2026-10-19 の試験で 4.1.2 だけと確定）はレベル A の基準である。部分適合の記述で除いた部分の A の不足が、ガイドラインの「レベル A に準拠していることが前提」に掛かるかは、ガイドラインに書かれていない（除いた部分を除けば A を満たすので掛からないと読むのが自然だが、WAIC の解説で確かめていない）。§7 の A-6 に含める。

- **対応度は試験の結果であって、宣言ではない。** 試験（§4）を終えるまで `/accessibility/` に対応度を書かない。改修中は「対応中」とも書かず、ページそのものを出さない（L4-1 で確定させてから公開する）。
- **試験の結果が古くなったら書き直す**（§6）。UI を変えたのに試験日を更新しないと、表明が事実と食い違う。

## 2. 達成基準と、このサイトの対応表

### 2.3 該当しない基準と理由

**この節の判定は 2026-10-19 の試験（Q2）で確かめ、確定した。** 当初は、V1 のベースラインと Wave 2 の実装を見るまで仮の判定にしていた（2026-10-18 にリードが決定）。

| 基準 | 理由 | 該当するようになる変更 |
|---|---|---|
| 1.2.1〜1.2.5 | サイトに音声・映像（`video`・`audio`・動画の埋め込み）が無い。**MorphSlider・MetaBalls は WebGL で描く動きで、映像ではない**（収録した映像・音声を再生しない。写真の切り替えは訪問者の操作だけで起き、写真そのものは `<img alt>` で同じ内容を出す）。ShapeBlur・GooeyNav・StatusMark も同じく映像ではない | 動画・音声・ポッドキャストを置く。記事に動画を埋め込む（Strapi の本文）。モーションの部品に収録した映像（`video` のテクスチャ）を使う |

### 3.2 新しいタブ・外部リンク

- **`target="_blank"` のすべてに、sr-only の告知を付ける。** 部品は `a11y` の `NewTabNotice`（props は `{ text }`。文言は `site-content/a11y.ts` の `NEW_TAB_NOTICE`。文言の正本は `01-content-spec.md` §12）。
- 対象（2026-10-18 の調査で 7 か所）: フッターの「ソースコード（GitHub）」（既存の告知を `NewTabNotice` に置き換える）、無料 DL ブロックの「ソースコードを見る（GitHub）」（`forms`・`source-dl` の 2 部品）、同意のチェックボックスの「プライバシーポリシー」、予約枠の注記の「プライバシーポリシー」、法務の外部リンク（`legal` の `RichTextView`）、記事本文の外部リンク（`blog/lib/body.ts`）、`CTAButton` の `external`。
- 見た目の印（外部リンクのアイコン）を付けるかは foundation が決める。付けるならアイコンは `aria-hidden="true"` にし、告知は文字だけで行う（告知が二重に読まれないように）。
- 「ソースコードを無料 DL」の CTA が `window.open` で zip を開く動き（`source-dl`）は、リンクの `href` が `#source-dl` なので新しいタブの告知の対象ではない。**ただし押したときに元のタブが無料相談へ移ることを、押す前に伝えていない**（3.2.5 は AAA で対象外）。§7 の未決定事項に残す。

### 3.4 reduced-motion（P-5）

- `prefers-reduced-motion: reduce` のときは、`global.css` で `transition-duration` と `animation-duration` を 0.01ms にする（0 にしないのは、`transitionend` を待つ処理を止めないため）。`scroll-behavior` も `auto` にする。
- Spinner は回転をやめ、文字で「読み込み中」と示す（文言は `01-content-spec.md` §12）。
- React Bits の部品は `useReducedMotion()` が真なら静止させる（§3.5）。
- 2.3.3（AAA）は対象外だが、前庭障害のある訪問者への配慮として最小の JS で行う。

### 3.5 React Bits とモーション（P-6・P-10）

振る舞いの正本は `05-motion-spec.md`。この文書の基準に効く規則だけを挙げる。

1. `useReducedMotion()` が真なら静止させる（2.2.2・P-5）。
2. 5 秒を超えて自動で動くものには `MotionPause` を付ける（2.2.2）。
3. 1 秒に 3 回を超えて点滅させない（2.3.1）。
4. 装飾の canvas には `aria-hidden="true"`（1.1.1）。意味を持つ部品（MorphSlider の写真、StatusMark の状態）は、canvas の外の HTML（`<img alt>`・ラジオのラベル・`role="status"` の「送信中…」）で同じ情報を出す（1.3.1・4.1.3）。StatusMark の形（`SendStatusMark`）はボタンの中で `aria-hidden`。
5. 文字を分割して動かす部品（`SplitText` など）は、元の文を `aria-label` か sr-only で 1 回だけ読ませ、分割した文字は `aria-hidden` にする（1.3.1）。
6. hover で起きることは `:focus-visible` でも起きる（2.1.1）。
7. WebGL が無い・JS が失敗したときも、静的な HTML で内容が欠けない（§1 の「依存しない技術」）。
8. 取り込んだ原本の a11y の変更には `// a11y:` の印を付ける（P-10）。

| 二重送信の防止 | 同上 | 同上 | 4.1.3 |
| 完了（無料相談） | 遷移先の `h1`（ページの移動として読まれる） | **完了の文は読まない**（`SendStatus` は送信中の「送信中…」だけを読む。完了のチェックの形は見せるだけ） | 2.4.3・4.1.3 |
| 完了（無料 DL。ブロックの中で置き換え） | 置き換えた結果の領域（既存の `tabindex="-1"`） | 見出しと本文を、フォーカスの移動で 1 回。`role="status"` とフォーカスの移動を同時に使わない。**完了の文（`送信しました` など）を足さない**（足すと 2 回読まれる。2026-10-18 に motion・integrations・リードで合意） | 4.1.3 |
| ご相談内容の文字数 | 動かさない | **残り 20 字以下になったときと、超えたときだけ**、見えている形（「1,985 / 2,000」）をそのまま読む。毎回の入力では読まない。新しい文言は作らない（2026-10-18 に integrations が提案） | 4.1.3 |

- **すべての欄に見えるラベル。** 姓と名は、まとめのラベル「氏名」の下にそれぞれ見えるラベルを付ける（文言は `01-content-spec.md` §5.1）。プレースホルダはラベルの代わりにしない。
- 必須は見た目の Badge「必須」に加えて `aria-required="true"`（`required` 属性はブラウザの既定の検証の吹き出しが §5.1 の文言と食い違うので使わない。使うなら `noValidate` を付ける。integrations が決める）。
- フォームに名前を付ける（`<form aria-labelledby>` で見出しを指す）。
- `autocomplete` は §2.2 の 1.3.5。
- フォームの送信は `page.route` で差し替えて試験する（計画の規則 7。送信先の実際の URL をネットワークの記録で確かめてから、パスで差し替える）。

### 3.7 見出し・ランドマーク・ページタイトル・言語

- **h1 は 1 ページに 1 つ。** 見出しの段を飛ばさない（h2 の次に h4 を置かない）。部品の見た目の大きさと段を分け、段は `level` プロパティで渡す。
- 記事本文（Strapi のリッチテキスト）の見出しは、`blog/lib/body.ts` で「直前の見出しより 2 段以上深くならない」ようにそろえる（執筆者の段の選び方に頼らない）。
- ランドマーク: `header`（バナー）、`nav`（名前付き）、`main`、`footer`。**同じ種類のランドマークの名前を重ねない。** Desktop のヘッダーの `nav` と Mobile のメニューの `nav` は同時に出ないので、どちらも「メイン」にそろえる（文言は `01-content-spec.md` §1.3・§12）。フッターの列の `nav` は列の見出しで名前を付ける（既存）。
- ページタイトルは `01-content-spec.md` §7。新しい 2 ページの title は §7 に足す。
- `<html lang="ja">`。英語だけの段落は `lang="en"`（3.1.2）。

### 3.9 ネイティブの HTML を優先する・文言を部品に持たせない

- ARIA は、ネイティブの要素で表せないときだけ使う（計画の規則 4）。`div` に `role="button"` を付けない。`button` を使う。
- **a11y のために React の island を増やさない**（Lighthouse の performance 0.9 と SEO 1.0 を落とさない）。静的な `.astro` で書けるものは `.astro` で書く。
- **sr-only の文・`aria-label` も画面の文言として扱う。** 正本は `01-content-spec.md` §12。**再利用する部品（`components/ui`・`marketing-ui`・`a11y`・`motion`・`forms` など）は既定値に文言を入れず、使う側から渡す**（H-16・H-31）。レイアウトに 1 つしかない部品の固定の名前（スキップリンク・`nav` の名前・メニューの開閉・パンくずの「ホーム」）は部品の中に置いたままでよい（H-31 の例外）

### 3.10 Cookie 同意バナー

2026-10-18 に integrations とリードが決めた。**計画の「撤回の手段が 2 回のキー操作以内で届く」はやめ**、次の 2 つを要件にする。

1. **全ページのフッターの「Cookie 設定」から、キーボードだけで撤回（「同意しない」）まで届く。**
2. **「Cookie 設定」でバナーを出し直したときは、フォーカスをバナーの見出しに移し、見出しと本文（`aria-describedby`）が読まれる。** 何のための画面かが分かってから選べるようにする。

- DOM の位置はスキップリンクの直後（告知帯より前）。見た目は下端に固定（2.4.3）。
- バナーの表示中は、フォーカスした要素がバナーに隠れないように `scroll-padding-bottom` を取る（2.4.11）。
- バナーの表示中は Chatwoot のランチャーを隠す（K4。既存）。

| 判定 | 意味 | チェックリストでの表記 |
|---|---|---|
| 適合 | 対象のすべてのページで、その基準を満たした | 「適合」 |
