# systematization-of-the-business-foundation

`SaaS`システムの販売事業`の`事業経営基盤`を`再帰的自己改善型`のシステムとして構築します。

## スキーム（運用体制と業務フロー）

- 役割の明確化: Webマスター（全体の構築・管理）、コンテンツディレクター（SEO・記事作成）、データアナリスト（CVR改善）の3つの役割・責任範囲を定義。

- 標準化された更新ワークフロー: 「企画 → 執筆/デザイン → 承認（ダブルチェック） → 公開」の手順を標準化し、情報の正確性確保と誤更新リスクを回避。

- 定期的なPDCA運用: 週次のコンテンツ投入・ABテスト、月次のGA4/MAデータに基づくCVR（コンバージョン率）改善会議の定例化。

- ガバナンス・セキュリティ運用: シングルサインオン（SSO）やアクセス権限制御を徹底し、担当者変更時の管理手順をマニュアル化。

- 役割分担の明確化:
  - SEOディレクター: 全体戦略、キーワード選定、カスタマージャーニー設計、KPI管理を担当。

  - コンテンツエディター/ライター: 記事構成案作成、取材、執筆、校正を実施。

  - エンジニア/Webデザイナー: サイト構造の最適化（テクニカルSEO）、表示速度改善、CTAデザインの実装。

- キーワード＆CV設計の標準化:
  - 検索意図を「潜在（課題探求）」「準顕在（手法比較）」「顕在・指名（サービス比較・導入検討）」に分類。

  - キーワードの温度感に合わせてCTA（無料相談、ソースコードの無料ダウンロード）を出し分け、MA/SFAへ即時トスアップするフローを構築。
    - 当初は「ホワイトペーパー、無料トライアル、デモ予約」の 3 種としていたが、**2026-10-01 に実態の 2 種へ改めた**（配布するのはホワイトペーパーではなく環境構築のソースコード、受けるのはデモではなく無料相談、**無料トライアルは提供していない**）。設計は `MarketingDepartment/WebsiteOperations/docs/RequirementDefinition/BA/04-business-processes.md` の「CTA 出し分けマトリクス」にある。
    - 無料トライアルを将来始める場合の設計（Mautic のステージ・セグメント・ポイント）は、同ファイルのトスアップ条件に「使わない」として残してある。

- 定期的なPDCA運用:
  - 月次の順位・流入・CVR分析に基づき、過去記事のリライトや内部リンク構造の最適化を定例業務化。

## システム（組み込むツール群）

- CMS: Strapi
- MA: Mautic
- アクセス解析: Google Analytics 4（GA4。流入・ページ・参照元の数字の正本。2026-10-06 に Umami から切り替え）
- ABテスト・例外の監視・記事のイベント・実測の Core Web Vitals: PostHog
- Web接客 / チャット: Chatwoot
- フロントエンドフレームワーク / SSG: Astro
- ワークフロー自動化 / iPaaS: n8n
- 競合・検索市場調査: OpenSEO
- SEO・パフォーマンス自動監査ツール: Google Search Console, Lighthouse CI
- マイニング: XMRig（**本システムの完成後に追加**。下の「マネタイズモデル」）
- マイニングプール（EVM 対応トークンへの変換）: unMineable（SaaS。**本システムの完成後に追加**）
- ウォレット / ダッシュボード: thirdweb（SaaS。**本システムの完成後に追加**）

## 再帰的自己改善として模倣する組織・サービス

- インフラ・CDNサービス: Cloudflare, Vercel（表示速度の高速化、DDoS攻撃対策、SSLの自動化）。
- デザイン・制作基盤: Figma（プロトタイプ共有と共同編集）、Canva/Adobe CC（バナー・アイキャッチ制作）。
- SEO / マーケティングコンサル: 戦略立案やキーワード選定に関する専門知見の導入。
- 保守・セキュリティ代行: サーバー監視や障害時の緊急対応サポート。
- SaaS/BtoB特化型コンテンツ制作代行: 専門知識を要する業界記事やユーザー事例・取材記事作成の外部ライター・編集プロダクションの活用。
- テクニカルSEO開発代行: Core Web Vitals（表示速度）改善や構造化データ実装など、スポットで専門知識が必要な開発業務の外注。

## マネタイズモデル（2026-10-03 に追加。本システムの完成後に着手）

| 流れ | 利用者 | ComeGin |
|---|---|---|
| キャッシュアウト | 本プロジェクトのシステムを動かすサーバ代、発注代金 | 本プロジェクトのデモアプリのサーバ代 |
| キャッシュイン | 採掘によって得られたトークンの配布 | 採掘によって得られた暗号資産、受注による報酬 |

- **利用者**は、無料 DL したソースコードでこの基盤を自前のサーバに立てた事業者を指す。**採掘は利用者が明示的に同意したサーバでだけ動かし、既定では無効にする。** ComeGin の AWS（本番・デモアプリ）では採掘しない（AWS の規約が採掘を禁じているため）。
- 採掘の成果（XMR）は unMineable が **POL（Polygon）** に変換して ComeGin のウォレット（thirdweb）へ払い出す。利用者には貢献量に比例した**譲渡できないポイント**を付与し、ComeGin への発注代金の値引きにだけ使えるようにする（暗号資産の交換・預かりを ComeGin が行わないため）。
- 着手の前に、弁護士・税理士・AWS の規約の 3 つの確認を通す。
- 設計: `MarketingDepartment/WebsiteOperations/docs/RequirementDefinition/AA/05-application-decisions.md` の ADR-20、`docs/superpowers/specs/2026-10-03-monetization-design.md`
