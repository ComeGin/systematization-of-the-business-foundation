# 公開サイトの動きの作り込み（Aceternity UI を参考にしたアニメーション・モーフィングと VRM アバター）設計

- 日付: 2026-10-19
- 対象: `frontend/verdant-virgo`（公開サイト。本番は S3 ＋ CloudFront）
- 前提の作業: JIS X 8341-3 の AA 改修（ブランチ 33、`docs/superpowers/plans/2026-10-18-jis-x-8341-3-accessibility.md`。動きの規則と `src/modules/motion/` はここで作った）
- ★ の付いた項目は、ユーザーが判断を任せた範囲で設計者が決めたもの。それ以外はユーザーが決めた。

## 1. 目的

公開サイトは「ページに着いた瞬間」と「スクロールして読み進める間」のどちらも静かすぎて、UX として物足りない。
Aceternity UI の部品を参考に、アニメーションとモーフィング（形が変わりながらつながる動き）を全ページに作り込む。
あわせて、代表（亀谷 銀大）の VRoid アバターを画面の端に出し、訪問者の動きに合わせてエモート（身ぶり）をさせる。

ねらい: ブランドガイドライン §2.7 の「近い ― 顔と名前で仕事をする」を、写真よりも一歩進めて体験にする。
とくにトップとサービスのページで、「この人に任せて大丈夫か」を判断する前の最初の数秒に期待を作る。

## 2. ゴール・非ゴール・アンチゴール

### ゴール

- 規約・ポリシーの 2 ページを除く**すべてのページ**で、訪問時と閲覧中に動きがある。
- 下の §6 の表のとおり、Aceternity UI の 14 種（Hero／CTA／Team／Feature／Pricing／Contact／Blog／Blog Content／Stats の各 Section、3D Card Effect、3D Globe、3D Animated Pin、3D Marquee、Backgrounds & Effects）がサイトのどこかで使われている。
- VRM アバターが規約・ポリシー以外の全ページの端に居て、訪問者の操作に応じてエモートをする。
- ページ間の移動が、形の変わる遷移でつながる。

### 非ゴール

- 文言・料金・ページ構成を変えること（文言の正本は `src/modules/site-content/`。仕様書から一字一句写したもので、この作業では触らない）。
- アバターを会話させること（チャットは Chatwoot の役目）。アバターは情報を持たず、飾りである。
- Lighthouse の performance 0.9 を守ること（§4 のとおり、動きを優先するとユーザーが決めた）。

### アンチゴール（動いても失敗とみなすもの）

- JIS X 8341-3 の AA 改修で通したもの（axe 違反 0、e2e、NVDA での確認）を壊すこと。
- 規約・ポリシーの 2 ページに動きやアバターが出ること。
- B のページ（§5）が、トップ・サービスと同じ華やかさになること。B のページはガイドラインの「誠実・静か」に従う。
- 動きのせいで h1・本文・LCP の写真が見えるまで待たされること（文字はアニメーションで隠さない。初めから読める状態で出し、飾りだけを動かす）。
- GA4・PostHog・Chatwoot・Cookie 同意の動作が変わること。

## 4. 制約

### 4.1 アクセシビリティ（AA 改修の規則をそのまま守る）

`docs/BasicDesign/DesignSpec/website/05-motion-spec.md` の「動きの規則」と計画書 P-4〜P-6・P-10 を守る。要点は次のとおり。

- reduced-motion（`prefers-reduced-motion: reduce`）のときは動きを止める。判定は `a11y` モジュールの `prefersReducedMotion()`／`useReducedMotion()` を使う。CSS は `global.css` の既存の規則で 0.01ms になる。
- 5 秒を超えて自動で動くものには `MotionPause` を付ける（2.2.2）。押した結果は `sessionStorage` に覚える（try/catch で囲む）。
- 1 秒に 3 回を超えて点滅させない（2.3.1）。光る・きらめく系（Sparkles・Meteors・ボタンの発光など）は、明るさの変化の周期を 1 秒以上にする。
- 装飾の canvas・SVG には `aria-hidden` を付ける。文字を分割して動かす部品は、元の文を 1 回だけ読ませる（`aria-label` か sr-only）。
- 画面外とタブが非表示のときは止める（`run-when-visible.ts`）。
- ポインターに反応する動き（3D Card の傾きなど）は、キーボードのフォーカスでも同じ見え方の変化を起こすか、動きに意味を持たせない。
- フォーカスリングを動きで隠さない。傾く・浮く要素のフォーカスリングが欠けないこと。

### 4.2 ブランド

- B のページは `ブランドガイドライン v1.4` のとおり。とくに §5.4（青は面積の 10% まで）、§7.3（影は 3 段まで。立体を重ねない）、§2.7（誠実・静か）。
- A のページはガイドラインの例外とする（U-5）。ただし例外にするのは**動き・光・立体の表現だけ**で、次はどのページでも守る:
  - パレット外の色を使わない（光も `brand.sky`・`brand.blue`・`brand.gradient` から取る）。
  - 本文の文字のコントラスト 4.5:1（ガイドライン §1.3 の優先順位 1「読めること」）。
  - ロゴの禁止例 §4.6（回転・傾斜・光彩・ドロップシャドウをロゴにかけない）。**3D Card・3D Marquee・3D Pin でロゴを傾けない**。他社のロゴも新しく載せない（3D Marquee は今の文字のバッジを流す。§6）。
  - 書体・文字サイズ・組版（§6）。
- ★ アバター（§7）は、代表の分身として全ページ（C を除く）に出すので、A／B を問わず例外に含める。B のページでの例外はアバターだけ。
- ★ 例外は ADR-29 として `docs/RequirementDefinition/AA/05-application-decisions.md` に残し、ガイドラインに足す節の文案（「9.5 Web サイト」の下に「動きと装飾の例外」）を作る。ガイドラインの正本（`~/ComeGin/comegin/documents/ブランドガイドライン.md` と Drive の PDF）の更新はユーザーが行う。

### 4.3 性能

- U-3 により、`lighthouserc.cjs` の performance の判定を変える。★ `"categories:performance"` を `error` から `warn` にし、計測は続ける。accessibility・best-practices（0.9）と **SEO（1.0）は error のまま**。
- それでも次は守る:
  - h1・本文・LCP の写真は最初の HTML に入れ、JS を待たずに読める。
  - 重い部品（three.js を使う 3D Globe とアバター、WebGL）は、最初の描画の後に読む（`client:idle` か `client:visible`。置き場所に合わせる）。
  - three.js はアバターと 3D Globe で同じチャンクを共有する。
  - CLS を出さない（飾りは `position:absolute` で重ね、場所を先に確保する）。
- performance を warn にしたことは、非機能要件の文書と、観測のエージェント（`quality-checker`・`seo-auditor`）が読むしきい値の記述にも反映する。反映しないと、毎週の観測が performance の未達を起票し続ける。

### 4.4 構成とリポジトリの規則

- **モジュールごとにフォルダを作る**（ユーザーの条件）。§9 の構成に従う。
- 調べもの・確認には、必要に応じて検索と `astro-docs`・`shadcn`・`pmndrs`（three.js と React Three Fiber の文書）・`blender`・`pywinauto-host`・`pdf`・`docling`・Google Drive・`playwright`・`playwright-host` の各 MCP を使う（ユーザーの条件）。インタラクションデザイナーの視点（体験の筋書き・手触り・止められること）で判断する。
- 取り込んだ原本と自作の差分を分ける（計画書 P-10）。原本は `vendor/<出典>/<Name>/` に置き、冒頭に出典の URL と取り込み日を書く。a11y と性能のための変更には `// a11y:`／`// perf:` の印を付ける。ページとレイアウトは `motion`・`avatar` の `index.ts` が公開するラッパーだけを使う。
- 依存の追加は pnpm 11 と `pnpm-workspace.yaml` の `minimumReleaseAge`・`trustPolicy` に従う。
- 成果物（Astro）はクラウドで動く。アバターとモーションのファイルは Astro と一緒に S3 ＋ CloudFront で配る（データの置き場を AWS にする条件に合う）。新しい AWS の資源は作らない。
- ★ アバターのファイルは `public/` ではなく `src/modules/avatar/assets/` に置き、Vite の資産として読む（`?url`）。こうすると `_astro/` にハッシュ付きの名前で出て、デプロイ手順（`cloud/README.md` §4.14）の `max-age=31536000,immutable` が効く。`public/` は `max-age=0` になるため使わない。
- リポジトリのルール: この作業ではビルド・テストの実行とテストコードの追加・更新を許可されている（U-11）。**デプロイ（`sam deploy`・S3 への同期など）はしない**。git の状態を変える操作はしない。
- 確認の最低線: `pnpm a11y` で axe 違反 0・e2e 全合格（新しい部品とアバターの e2e を `e2e/a11y/` に足す。reduced-motion・一時停止・キーボードのフォーカス・C のページで出ないこと）。Lighthouse は、ほかの build・ブラウザを止めた静かなときに測る（`benchmarkIndex` を確かめる）。NVDA での確認は、変えた部品について最後にユーザーに頼む。

## 5. ページの区分け

| 区分 | ページ | 動きの強さ |
|---|---|---|
| **A. 華やか** | トップ `/`、サービス一覧 `/services/`、サービス詳細 `/services/{environment-setup,development,consulting,partnership}` | Aceternity らしい光・立体・粒子・文字のにじみ出しまで使う |

### A と B の手触り（試作で承認済み。U-6）

試作のファイルは `.superpowers/brainstorm/2379075-1792358490/content/zoning.html`（追跡しない）。

- **A（ヒーローの例）**: navy.900 の地。グリッドが中心から薄く広がる。スポットライト（`brand.sky` の放射）がゆっくり漂う。光の筋が横切る。見出しは語ごとに、ぼかしから焦点が合いながら現れる。ボタンの縁が周期的に淡く光る。
- **B（同じヒーロー）**: neutral.50 の地。左上に blue.500 の短い罫が引かれる。見出し → 本文 → ボタンの順に、少し下からふわっと上がる（`--motion-ease-standard`、`--motion-duration-large`）。ボタンはホバーで 2px 浮き、`shadow.lg` が付く。

数値（時間・緩急）は `theme.css` の `--motion-*` と `motion/lib/tokens.ts` にそろえる。足りない値は新しいトークンとして足す（部品ごとに数値を書かない）。

## 7. アバター

### 7.1 見せ方

- 画面の**左下**に置く（★。右下は Chatwoot のウィジェット、下端は Cookie 同意のバナーが使う。同意のバナーが出ている間は `--consent-banner-height` の分だけ上に逃がす）。
- 背景が透明な canvas に、全身か膝上を描く。canvas は `aria-hidden`。アバターはサイトの情報を持たない。
- 視線（VRM の lookAt）はポインターを追う（A だけ。★）。まばたきと呼吸のような小さな動きを常に続ける。

### 7.2 A と B の違い（★。U-8）

| | A（トップ・サービス） | B（料金・会社紹介・お問い合わせ・ブログなど） |
|---|---|---|
| 大きさ | 大きめ（Desktop で高さ 280px 前後） | 小さめ（同 180px 前後） |
| エモート | ページに着いたら手を振る／料金・プランの節まで読み進めたらうなずく／主 CTA にホバーかフォーカスしたらそちらを指さす／しばらく何もしなければ考えるしぐさ | ページに着いたら手を振る／送信が終わったら喜ぶ（お問い合わせの完了と無料 DL の送信） |
| 視線 | ポインターを追う | 正面のまま |
| たたむ | できる | できる |

- エモートは 1 回ずつ終わる短い動き（2〜3 秒）で、終わったら待機の動きに戻る。同じエモートを短い間に繰り返さない。
  - （2026-10-19 の裁定 R17）**着いたときの「手を振る」はセッションで 1 回だけ**（`sessionStorage` の `avatar:greeted`）。ページを移るたびに island が作り直され、毎ページ挨拶するとうるさいため。
  - （2026-10-19 の裁定 R18）Mixamo のクリップは 2〜3 秒より長いものがある（考えるは約 13 秒）。**1 つの再生中に次の合図を受けない間は、エモートごとのクリップの長さ**にする（いちばん長いクリップに全部を合わせると、挨拶の直後の料金の節のうなずきが捨てられたため）。**受理されなかった合図は消費しない**: 料金の節は受理されるまで見張り続け、画面にある間は 1 秒ごとに出し直す。何もしないときの合図も、操作が無い限り 1 秒ごとに出し直す。着いた・CTA・送信の合図は、その時の 1 回だけ。
- （2026-10-20 の裁定 R20。ユーザーの指示）**上の表のエモートと R18 の合図の受け方を改めた。** 出たら手を振る（R17 のまま）→ 直立 → 操作が 15 秒無ければ待機の呼吸（BreathingIdle）→ 操作があれば直立。アバターを押す（クリック・タップ）と、ほかの 5 本から 1 本。ページの印・CTA・送信の成功では動かさない。A と B で同じ。あわせて、スクロール（ホイール）・ピンチでアバターの枠を拡大・縮小できるようにした（枠自体を大きくする。ユーザーの選択）。詳細は `05-motion-spec.md` §10.2。
- 待機の動き（呼吸・まばたき）は 5 秒を超えて続くので、**`MotionPause` を付ける**（U-4）。一時停止の間は最後の姿勢で止まる。
- 「たたむ」ボタンでアバターを小さなアイコンにできる。たたんだ状態は `sessionStorage` に覚え、ページを移っても保つ。
- 規約・ポリシーの 2 ページでは出さない（読み込みもしない）。

### 7.3 端末と設定ごとの扱い

- **reduced-motion**: three.js を読まず、あらかじめ書き出した静止画（PNG／WebP。手を振る直前の姿勢）を出す（★）。
  - （2026-10-19。実装で追認）一時停止のボタンは出さないが、**「たたむ」ボタンは残す**（静止画が本文に重なったまま消せないことを避ける）。
- **スマホ（Mobile の幅、またはポインターの無い端末）**: 最初は顔のアイコン（静止画）だけを出す。押したら 3D を読み込んで出す（★。軽くした後でも約 4.3MB を勝手に読まないため）。
  - （2026-10-19 の裁定 R19。ユーザーの選択）**出した後は高さ 120px に小さくし、スクロールしている間は左の画面外へ逃がして、止まったら戻す。** 動画の確認で、左下のアバターが本文や料金カードのボタンに重なったため。逃がしている間は描画を止める。アバターのボタンに見えるフォーカス（`:focus-visible`。キーボードで入ったとき）がある間は逃がさず、Tab で入ったら戻す（2.4.7）。タップの後のフォーカスは対象にしない（タップで出すとフォーカスがたたむボタンへ移り、対象にすると Mobile では一度も逃げないため。2026-10-19 の Task 10b）。
- **JS が無いとき**: 何も出さない。
- 読み込みは最初の描画の後（`client:idle`）。`.vrm` とモーションは `_astro/` のハッシュ付きの名前で 1 年キャッシュされ（§4.4）、ページを移ってもブラウザのキャッシュから読む。

### 7.4 ほかの部品との関係

- 会社紹介の 5-7 メンバーには代表の写真がある。アバターと写真が同じ画面に並ぶので、アバターはこの節が見えている間は小さくなる（★）。
- フォームの入力欄・送信ボタン・フォーカスリングにアバターが重ならない。重なる幅（狭い画面）では自動でたたむ。
- 印刷（`@media print`）では出さない。

### 7.5 モデルとモーションの素材

- モデル: Drive の `Assets/Model/亀谷銀大_VRoid.vrm`（約 11MB）。★ **目標 4MB 以下、上限 6MB**（上限を超えるなら表情・揺れものを削る。CloudFront の Free プランの転送量に効くため）に軽くする（テクスチャを 1024px に、使わない表情・ボーンの整理）。手段は VRoid Studio の書き出し時の軽量化（pywinauto-host MCP で操作）か、Blender の VRM Add-on での書き出し。VRM の拡張（表情・揺れもの・視線）を落とさない手段を選ぶ。
- **モーション（U-14）**: Mixamo（Adobe）のモーション 7 本。Waving→手を振る、HeadNodYes→うなずく、Pointing→指さす、Thinking→考える、Victory→喜ぶ、StandingGreeting→全身を見せる、BreathingIdle→待機。
  - Mixamo の FAQ では、個人・商用・非営利のプロジェクトにロイヤリティなしで使え、クレジットの求めも無い（ここまでは FAQ で確かめた）。キャラクターやアニメーションを単独で・編集できる形で配ること、素材として売ることは認められていない、という制限は、出どころを確かめていない（次の箇条）。FBX はリポジトリに入れず（`.gitignore`）、サイトには VRM の骨格へ当て直した JSON のクリップだけを、アバターの再生のために配る。
  - （2026-10-19 に改めた）**ただし、2026-10-19 に見た FAQ のページ（2021-09-14 更新）には、この制限の文言が見当たらなかった**（`src/modules/avatar/assets/README.md`）。JSON のクリップもブラウザから取り出せる動きのデータである。**公開前に、ユーザーが Adobe の利用条件で正確な制限とクレジットの要否を確かめる**（未決定。`05-motion-spec.md` の MO-8、ADR-29 の未決定事項）。確かめるまで、条件を満たしているとは扱わない。
  - 変換はリポジトリの Node のスクリプト（three の `FBXLoader` ＋ three-vrm の公式サンプルの対応表）で行い、Blender を使わない。Blender の Mixamo Rig Add-on は、動きを手で直したくなったときの予備。
  - VRoid 公式の 7 種セット（U-12）は、Readme の禁止事項「許可なく取り出せる状態で二次配布すること」のため使わない（U-13）。7 種セットのクレジットは不要になった（Mixamo のクレジットの要否は上の未確認の項）。
- ★ モーションとアバターは、ほかの作業と切り離した段にする。出来上がったら Desktop と Mobile の動画を撮り、**ユーザーが見て承認する区切り**を置く。
- 読み込み: `three`（`GLTFLoader` を含む）、`@pixiv/three-vrm`。（2026-10-19 に改めた）モーションは `.vrma` ではなく、VRM の骨格へ当て直した JSON のクリップ（`src/modules/avatar/lib/clip.ts`）で再生するので、`@pixiv/three-vrm-animation` は使わない（依存から外した）。
- 静止画（reduced-motion とスマホの最初のアイコン）は、three.js で描いた 1 コマを書き出すか Blender で書き出す（作る人の判断）。
- **作業の前提**: 2026-10-19 の時点で、Blender の MCP（`10.0.2.2:9876`）と pywinauto-host の MCP はつながっていない。モデルの軽量化を MCP で行う場合は、その前にユーザーがホストの Blender（MCP のアドオンと VRM Add-on を有効にして）か pywinauto-host を起動する。
- ★ VRM のメタ情報のライセンス表示は、軽量化のついでに「アバターとしての利用は本人のみ・再配布不可・商用不可」に設定する（U-10 で配布は受け入れたが、利用の許諾までは出さない）。

## 8. ページのつなぎ（モーフィング）

- ★ すでに入っているブラウザ標準の文書間の View Transitions（`global.css` の `@view-transition { navigation: auto; }`、ヘッダーの `view-transition-name: site-header`）を広げる。**Astro の `ClientRouter` は使わない**（GA4・PostHog・Chatwoot・同意の読み込みがページ遷移を前提にしているため）。
  - （2026-10-19 の裁定 R11）`@view-transition` は `global.css` から外し、`BaseLayout` が区分 C 以外のときだけ head に出す（C のページは opt-in しない）。
- 形をつなぐ組（例）:
  - トップ・サービス一覧のサービスカード → サービス詳細の導入ヒーロー（カードの見出しが、詳細の h1 へ形を変える）。**アイコンはつながない**（2026-10-19 の裁定 R13。サービスカードにも詳細の導入ヒーローにもアイコンが無く、足すと見た目と文言の仕様の変更になるため。最初の案は「見出しとアイコン」）
  - ブログのカード → 記事の見出しとアイキャッチ
  - 料金カードの申し込みボタン → お問い合わせの h1（料金カードはサービス詳細へリンクしていないため。★）
  - CTA ボタン → お問い合わせの h1
- `view-transition-name` はページの中で一意にする（一覧では、押したカードにだけ名前を付ける）。
- C のページ（規約・ポリシー）へ入るとき・出るときは、形をつながない普通の切り替えにする。
- reduced-motion では動かさない（`global.css` の既存の規則）。対応していないブラウザは普通の遷移になる。

## 9. モジュールの構成

```
src/modules/
  motion/                         既存。動きの部品の公開口
    vendor/react-bits/<Name>/     既存
    vendor/aceternity/<Name>/     新規。Aceternity の原本（出典の URL・取り込み日・ライセンスを冒頭に）
    sections/<Kind>/              新規。14 種ごとの包み（Hero・Stats・Feature・Pricing・Team・Contact・Blog・BlogContent・Cta・Card3d・Globe3d・Pin3d・Marquee3d・Backgrounds）。A／B の強さを props（intensity: "vivid" | "calm"）で切り替える
    islands/                      既存。React の island
    lib/                          既存。tokens・run-when-visible など
  avatar/                         新規。VRM アバター
    components/AvatarDock.astro   置き場所の包み（client:* はここだけが持つ）
    islands/AvatarStage.tsx       three.js の描画、エモートの切り替え
    lib/emotes.ts                 エモートの定義と、ページ・操作との対応
    lib/triggers.ts               着いた・読み進めた・CTA に触れた・送信できた、の検知
    lib/types.ts
  page-transition/                新規（★）。View Transitions の名前の付け方と、C のページで外す処理
  avatar/assets/                  軽くした .vrm、.vrma、静止画（Vite の資産として読む。§4.4）
```

- ページ・レイアウトは `motion`・`avatar`・`page-transition` の `index.ts` が公開するものだけを使う。
- 「A／B／C のどれか」は、ページの側が `BaseLayout` に渡す（★ `motionZone: "vivid" | "calm" | "none"`）。部品は自分でページを判定しない。
- ★ 送信できたことの検知: 無料相談は送信後すぐ `/contact/thanks` へ移るので、完了画面に着いたことで「喜ぶ」を出す（`avatar` がページの印を読む）。無料 DL はページを移らないので、`forms` が送信の成功時に DOM のイベント（例 `comegin:form-success`）を `document` に出すよう足し、`avatar` がそれを購読する。今の `forms/lib/events.ts` は PostHog への送信だけで、購読できるイベントを出していない。`forms` から `avatar` を直接呼ばない。

## 11. 作る人に任せること

- Aceternity のどの部品を何個取り込むか（14 種を満たす範囲で、無料のものから選ぶ）と、A のページの中での組み合わせ方。
- 各動きの時間と緩急（トークンの範囲で）。新しいトークンの名前。
- アバターの正確な大きさ・位置・カメラの画角。モーションの細部。
- モデルを軽くする手段（VRoid Studio か Blender か）。
- 3D Globe の色・点の密度・回る速さ。

## 12. 設計者の判断（★）の一覧

ユーザーが読むときに確かめてほしい判断。

1. 14 種の置き場所（§6）
2. アバターの A／B の違い、視線は A だけ（§7.2）
3. アバターは左下（§7.1）
4. reduced-motion では静止画、スマホは押してから 3D（§7.3）
5. 会社紹介のメンバー欄が見えている間はアバターを小さくする（§7.4）
6. ページのつなぎはブラウザ標準の View Transitions で、`ClientRouter` は使わない（§8）
7. `lighthouserc.cjs` の performance を error から warn にする（§4.3）
8. ブランドの例外を ADR-29 にし、ガイドラインの文案を作る（§4.2）
9. モジュールを `motion/sections/`・`avatar/`・`page-transition/` に分け、区分は `BaseLayout` の `motionZone` で渡す（§9）
10. 3D Marquee は今の文字のバッジを流し、他社のロゴを足さない（§6）
11. 3D Globe は大阪のピンだけで、弧を出さない（§6）
12. アバターはブランドの例外に含め、B のページにも 3D で出す（§4.2）
13. アバターは目標 4MB・上限 6MB。モーションはユーザーの承認の区切りを置く（§7.5）
16. 7 種セットとエモートの対応、「撃つ」などを使わないこと、クレジットの置き場所（§7.5）。**U-14 で 7 種セットを使わなくなったため、この判断は無くなった**
17. VRM のメタ情報を「本人のみ・再配布不可・商用不可」にする（§7.5）
18. Stats はトップ 1-8 の数値カードとブログ一覧 7-3 の数字に置く（§6。トップ 1-4b には数字が無かったため）
14. アバターのファイルは Vite の資産にして 1 年キャッシュ（§4.4）
15. 送信の検知は完了画面への到着と、`forms` が出す DOM のイベント（§9）
