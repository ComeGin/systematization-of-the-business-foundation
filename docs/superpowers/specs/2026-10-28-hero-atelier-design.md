- 前提の作業: 動きの作り込み（`2026-10-19-aceternity-motion-design.md`。A／B／C の区分・アバター・ページの形のつながり）、JIS X 8341-3 の AA 改修（`docs/superpowers/plans/2026-10-18-jis-x-8341-3-accessibility.md`）

## 1. 目的

`HERO` 分類（トップのヒーロー・告知バナー・下層ページの導入ヒーロー）を、Favorite Website Awards を受賞できる水準に仕上げる。
第 1 版では机の上の模型を外から眺めたが、第 2 版では**訪問者がデザイナーのアトリエの中に立ち、一人称で歩く**。

ねらいは第 1 版と同じく「技術力を見て、自社で使いたいと感じて帰ること」。
ユーザーの言葉では、頼みたいと思うきっかけは「**このサイトでの体験**」と「**過去の実績**」の 2 つ。
したがって、歩く・見る・押す、の手ざわりそのものが技術の証明であり、つなぎ目や破綻はそのまま「この会社に頼むと、こうなる」という印象になる。
インタラクションデザイナーの視点（触ったときの手応え・つながり・意味のある動き）で作る。

## 2. ゴール・非ゴール・アンチゴール

### ゴール

- トップの 1-3 ヒーローが、画面いっぱいの「デザイナーのアトリエ」になる。訪問者は空間の中央から一人称で歩き始める。
- 中央の前方に代表のアバター（`亀谷銀大_VRoid.vrm`）が立っている。押すとモーションをランダムに再生する。
- マウスを乗せる（スマートフォンでは長押し）と前へ進む。置き物にマウスを乗せる（タップする）と画像付きの Tips が出て、Tips を押すとそのページへ移る。
- 天井（空）が訪問者の時間帯で変わり、夜は星空がきれいに見える。
- 道の奥の手前に実績の展示の壁があり、行き止まりは相談の席。
- 下層ページの冒頭は、同じアトリエの別の場所の静止画になる。トップで Tips を押してから下層ページが出るまでが、カメラの移動としてひと続きに見える。
- 画面の端のアバター（`AvatarDock`）はサイト全体から無くなる。

### 非ゴール

- 1-3 以外のトップのセクション（1-4a 以降）を作り直すこと。第 1 版で移した写真の置き場所（H-12 の決定）も変えない。
- 既存の文言（タグライン・h1・本文・CTA のラベル）を変えること。新しく足す文言（Tips・展示の壁の額）はユーザーの確認を通す。
- 規約・ポリシー（C の区分）を変えること。
- Lighthouse の performance 0.9 を守ること（ADR-29。動きを優先する。ただし §10 の予算は守る）。
- 音を鳴らすこと（★。自動再生の音は訪問者の環境を乱す）。
- 道を分岐させること・自由に歩き回れること（★。一本道。§6.2）。

### アンチゴール（動いても失敗とみなすもの）

ユーザーが挙げた 2 つ（第 1 版の H-10 を引き継ぐ）:

1. **論理的に破綻している。**
   - 置き物と Tips と移り先のページが、1 対 1 で対応していない（机を押したのに別の話のページへ行く、など）。
   - Tips の画像（移り先の場所）と、実際に移った先の冒頭の静止画が違う。
   - 架空の実績・架空の数値が出る（GL §8.4）。許可の無い会社の名前が出る。
   - 代表のアバターが同じ画面に 2 人いる。
   - 空の時間帯と室内の光が合っていない（夜の空なのに昼の日差しが差す、など）。
2. **シームレスでない。**
   - 読み込みの途中で、白い枠・構図のずれ・素材の切り替わりが見える（ポスター → 立体の切り替えを含む）。
   - Tips を押してから下層ページが出るまでに、絵がいったん途切れる・別の角度へ飛ぶ・時間帯が変わる。
   - 動きを減らす設定・スマートフォン・JS なし・WebGL なし・遅い端末のどれかで「壊れた」「別物」に見える。
   - 前へ進むときにカクつく、急に止まる、置き物を通り抜ける。

これまでのアンチゴールも引き継ぐ:

- JIS X 8341-3 の AA 改修で通したもの（axe 違反 0、e2e、NVDA での確認）を壊すこと。
- h1・本文が、立体の読み込みを待たないと読めないこと。
- GA4・PostHog・Chatwoot・Cookie 同意の動作が変わること。
- ページのスクロールを乗っ取ること（★。ホイールと縦のスワイプは、いつもどおりページを送る。前へ進む操作には使わない）。

## 4. 制約

- **文字は HTML。** タグライン・h1・本文・CTA は最初の HTML に入り、立体を待たずに読める（SEO 1.0、LCP、スクリーンリーダー）。立体の canvas は `aria-hidden`、押せるものは canvas の上に重ねた本物の `<button>`／`<a>`（第 1 版と同じ作り）。
- **動きの規則（05-motion-spec.md §2）を守る。** 5 秒を超えて自動で動くもの（星のまたたき・アバターの待機・ランプの揺らぎ）には一時停止ボタン（`MotionPauseFor`）。reduced-motion では静止画。JS なしでも静止画。トップは A（vivid）のページなので、目を引く動きを 1 つの画面に複数置いてよい（ADR-29）。
- **three は 1 チャンク。** 既存の `motion/lib/three.ts` の `loadThree()` を使う（05-motion-spec.md §4）。three は最初の描画の後に動的 import で読む。
- **区分（A／B／C）は変えない。** 下層ページの冒頭は静止画なので、B のページにも置ける。サービス一覧・詳細（A）も、冒頭は静止画にする（A-14）。
- **誠実さ（GL §8.4）。** 架空の社名・人名・数値を出さない。実績は掲載許可が取れたものだけ（§8）。
- **素材のライセンス。** 配る glb・画像に入る素材は、再配布を含む Web での利用が認められたものだけ（§5.4）。
- **リポジトリの規則。** git の状態を変える操作（commit など）はしない。デプロイはしない。パッケージは pnpm。ビルド・テストの実行とテストコードの追加は A-19 の範囲で許可済み。
- **モジュールごとにフォルダを作る**（ユーザーの条件）。§12。
- **このヒーローは「成果物（Astro）」の一部であり、クラウド（S3 ＋ CloudFront）から配る**（ユーザーの条件）。アトリエの資産（glb・環境・静止画）も `_astro/` の資産として同じ配信に乗せる。新しいサーバーやデータの置き場は作らない（★）。

## 5. アトリエの構成

### 5.1 道筋（一本道）

上から見た図（★。寸法と左右の割り振りは作り手が調整してよい。順番と行き止まりは A-15・A-18 で決まり）:

```
                 [ 相談の席 ]          ← 行き止まり（A-15）
            [ 実績の展示の壁 ]          ← 奥の手前（A-16・A-18）
   [料金の机]                [記事の本棚]
   [サービス: 環境構築]      [サービス: 受託開発]
   [サービス: コンサル]      [サービス: 協業]
                 ( アバター )           ← 中央の前方（A-4）
   [会社の表札]      ● スタート          ← 空間の中央（A-3）
```

- スタートの目線は、人の立った目の高さ（約 1.6m）。正面にアバター、その奥に道筋と、いちばん奥の相談の席のランプがうっすら見える（★）。
- 道は 1 本の通り道（カメラが乗るレール）。左右の置き物のそばを通って奥へ進む（★）。

### 5.2 置き物と Tips と移り先（★）

置き物は、移り先のページと 1 対 1 で対応させる（アンチゴール 1）。

| 置き物 | 表すもの | Tips を押した移り先 | 移り先の冒頭の静止画（§7） |
|---|---|---|---|
| 会社の表札（スタートの脇） | ComeGin という会社 | `/about/` | 表札と、その奥に立つアバター |
| アバター（中央の前方） | 代表 | **移らない**。押すとモーション（§6.4） | ― |
| 環境構築のワークステーション（複数の画面とケーブル） | サービス: 環境構築 | `/services/environment-setup/` | その机 |
| 受託開発の作業台（ノート PC・設計図） | サービス: 受託開発 | `/services/development/` | その台 |
| コンサルティングのホワイトボード（付箋） | サービス: コンサルティング | `/services/consulting/` | そのボード |
| 協業の大きな共同の机（二脚の椅子・模型） | サービス: 協業 | `/services/partnership/` | その机 |
| 料金の机（見積もりの紙） | 料金 | `/pricing/` | その机 |
| 記事の本棚（本とスケッチ） | 記事 | `/blog/` | その本棚 |
| 実績の展示の壁（額） | 実績（§8） | 額ごとに決める（§8） | 壁（`/accessibility/` など、移り先のページの静止画） |
| 相談の席（行き止まり。机・二脚の椅子・ランプ） | 相談 | `/contact/` | その席 |

- サービス一覧（`/services/`）の冒頭の静止画は、4 つのサービスの置き物が並ぶ通り道を中ほどから見た絵（★）。トップの置き物からは直接移らない（トップの「サービス」の節やナビゲーションから来る）。
- 送信完了（`/contact/thanks/`）の冒頭は、相談の席にお茶が置かれた絵（★。「話が始まった」後の同じ場所）。
- 置き物の形・小物は作り手に任せる（§13）。ただし、それぞれが表す仕事が一目で分かること。

### 5.3 空と時間帯（A-10）

- 天井は大きなガラスの天窓で、部屋の中から空がそのまま見える（★。試作の絵）。
- 時間帯は**訪問者の端末の現地時刻**で、ページを開いた時に決める（★）。開いている間に境目をまたいでも切り替えない（つなぎ目になるため）。
  - 朝 5:00〜10:00、昼 10:00〜16:00、夕方 16:00〜19:00、夜 19:00〜5:00（★）。
- 空の作り方（★）:
  - 朝・昼・夕方: Poly Haven の HDRI（小さい解像度）を空と反射に使う。
  - 夜: 星は three の中で描く（点と、淡い天の川のテクスチャ）。HDRI の低い解像度では星がぼやけ、「星空がきれい」に届かないため。星は、ゆっくりまたたく（1 秒に 3 回を超えて点滅させない。2.3.1）。
- 室内の光も時間帯に合わせる（アンチゴール 1）: 昼は天窓からの日差し、夕方は斜めの暖かい光と灯り始めのランプ、夜はランプと画面の明かりだけ。
- HTML の層（文字の後ろの暗い覆い・Tips の札・一時停止のボタン）の色も時間帯のトークンに従う（★。「デザインシステムに精錬」〈A-1〉を、時間帯のトークン〈CSS のカスタムプロパティ〉として `theme.css` に持たせる形で満たす）。

### 5.4 素材の出どころ（A-2）

ユーザーの言う 4 つを、次のように作る（★）。

| ユーザーの言葉 | 中身 | 主に使うアドオン |
|---|---|---|
| Environment | 空（HDRI）・天窓の外・光の当たり方 | Poly Haven Assets（HDRI） |
| Scene | 部屋の形（壁・床・天井・天窓の枠）、置き物の配置、カメラのレール、時間帯ごとの光の組 | Blender で組む |
| Texture | コンクリート・木・紙・布・金属の質感 | Poly Haven Assets（テクスチャ）、Lily Surface Scraper（Poly Haven・ambientCG から） |
| Model | 机・椅子・本棚・画面・ランプ・小物・植物 | BlenderKit、Poly Haven Assets（モデル） |

ライセンスの方針:

- Poly Haven・ambientCG は CC0 なので、そのまま使ってよい。
- BlenderKit は**無料の素材**で、ライセンスが「Royalty Free」か「CC0」のものを使う（A-20）。有料・有料プラン限定の素材は使わない（★）。Royalty Free は素材そのものの再配布・販売を禁じているので、glb には製品の一部として焼き込み・まとめた形で入れ、素材単体を取り出して配る形（素材ごとの別ファイル）にはしない（★）。公開の glb から取り出されうる危険は、ユーザーが受け入れた（A-20）。
- BlenderKit のログインはユーザーが Blender で行う（A-20）。作業の最初に、ログイン済みかを確かめる手順を置く（★。2026-10-28 の時点では未ログイン）。
- Lily Surface Scraper は、CC0 の配布元（Poly Haven・ambientCG）からだけ取る。
- 使った素材の名前・ID・URL・ライセンスは `assets-original/atelier/README.md` と、配信側の `src/modules/atelier/assets/README.md` に残す。

## 6. トップのヒーロー（1-3）

### 6.1 構図

- ヒーローは画面いっぱい（高さ `100svh`）（★）。canvas はその背面、文字（タグライン・h1・本文・CTA）は左下に重ねる（★）。文字の後ろは時間帯のトークンの暗い覆いで、コントラストを満たす（1.4.3）。
- 文字は歩いても消さない（★。読みたいときに読める状態を保つ）。
- 最初の描画は、スタート地点の**ポスター**（その時間帯の静止画。§9 の 1）。立体の準備ができたら、同じ構図の最初のフレームを描いてからポスターを消す。

### 6.2 進み方（A-5）

- **マウス（★）**: canvas の、置き物でも文字でもない所にカーソルがある間、前へ進む。動き出しはゆっくり加速し、カーソルが外れる・置き物に乗ると、ゆっくり止まる（急に止まらない。アンチゴール 2）。カーソルの左右の位置で、視線がわずかに左右を向く。
- **スマートフォン（★）**: 置き物でない所を長押し（約 300ms）している間、前へ進む。指を離すとゆっくり止まる。縦のスワイプはページのスクロールのまま（`touch-action: pan-y`）。長押しでブラウザーのメニューや文字の選択が出ないようにする。
- **キーボード（★。JIS AA・2.1.1）**: canvas の上に「前へ進む」「入口に戻る」の本物のボタンを置く。矢印キー（↑ で進む・↓ で戻る）でも動ける。Tab で置き物のボタンを順にたどれる。
- **戻る（★）**: 少しでも進んだら「入口に戻る」のボタンを出す。押すとスタートへゆっくり戻る。
- **行き止まり**: 相談の席の前で止まる。それ以上は進まない。
- 進んだ位置は `sessionStorage` に残し、下層ページからブラウザーの「戻る」で帰ってきたら同じ位置から描く（★。つなぎ目を作らない）。
- 置き物・壁を通り抜けない（レールの上だけを動く）。

### 6.3 置き物と Tips（A-6・A-7）

- 置き物にカーソルを乗せる（タップする）と、置き物が少し明るくなり（★。縁の光）、そばに Tips の札が出る。
- Tips の中身: 移り先の冒頭の静止画を小さく、見出し、1〜2 行の説明、「見る」のリンク（★）。文言はユーザーの確認を通す。
  - 確認の時期（★）: Tips と展示の壁の額の文言は、Tips を作るタスクの**最初の手順**でまとめて案を出し、確認を通してから組み込む（第 1 版のパネルの文言と同じ進め方）。それより前のタスク（空間・歩く・書き出し）は文言に依存しない。仮の文言をファイルに書かない（GL §8.4。誤って公開されないため）。
  - 札の大きさは見出し 20 字・説明 60 字までを上限として先に決める（★）。案はこの上限の中で作る。
- Tips を押す（タップする）と、カメラがその置き物の正面（移り先の静止画と同じ位置・角度）へ動き、そのままページを移る（§9 の 3）。
- Tips は非モーダル（第 1 版のパネルと同じ）。Escape・外側を押す・ヒーローが画面から出る、で閉じる。外側を押して閉じたときはフォーカスを戻さない（第 1 版の最終レビュー I-1 の教訓）。
- スマートフォンでは、1 回目のタップで Tips、Tips のタップで移る（★。誤って移らない）。
- 押せる点（ボタン）どうしは 24px 以上離す（2.5.8。第 1 版の `layoutMarkers` を使う）。

### 6.4 代表のアバター（A-4・A-12）

- 中央の前方に、`亀谷銀大_VRoid.vrm` を軽くした既存の `avatar.vrm` を立たせる。待機のモーション（`idle`）で静かに立っている。
- 押す（タップする）と、身ぶりのクリップ（`greeting`・`nod`・`peace`・`point`・`show-full-body`・`think`。既存の `src/modules/avatar/assets/motions/`）から 1 つを**ランダム**に再生し、終わったら待機に戻る。**直前と同じクリップは続けて選ばない**（★）。再生中にもう一度押したら、いまのクリップを最後まで再生してから次へ（★）。
- カーソルを乗せると名前（「代表 亀谷 銀大」）の小さな札を出す（★。押すとページを移る Tips ではない）。キーボードでは本物のボタンとして Tab で届き、Enter で同じくモーションを再生する。
- アバターは道の上に立つので、歩く人はその横を通り過ぎる（通り抜けない。§6.2）。

### 6.5 一時停止と状態

- 動き続けるもの（星・アバターの待機・ランプ）は、一時停止のボタン（`MotionPauseFor`）で止まる。止めている間も、進む・Tips・移る操作はできる（★）。
- reduced-motion・JS なし・WebGL なし・遅い端末（第 1 版の `decideQuality` の判定）では、スタート地点のポスターと、置き物の Tips を並べた**一覧**（同じ画像・見出し・説明・リンク）を出す。内容は欠けない（A-18）。

## 7. 下層ページの冒頭（A-14）

- 各ページの冒頭の画像は、§5.2 の表の「移り先の冒頭の静止画」。トップと同じシーン・同じ光で、three に描かせて書き出す（第 1 版と同じ方法。§9 の 1）。
- 時間帯は 4 種類（朝・昼・夕方・夜）を書き出し、トップと同じ規則で出し分ける（★。Tips で移ったときに時間帯が変わると、つなぎ目になる）。JS が無いときは昼の絵（★）。
- 第 1 版では B の静止画を Desktop だけに出したが、第 2 版では **Mobile にも出す**（★。スマートフォンで Tips から移ったときのつなぎ目をなくすため）。
- 静止画は飾り（`alt=""`）。意味は見出しと本文が持つ。
- `/accessibility/` にも、実績の展示の壁の静止画を置く（★。壁の額から移る先になるため）。いまの `/accessibility/` は法務と同じ型（パンくず → h1 → 本文 720px。`01-content-spec.md` §4.11）で冒頭に画像の場所が無いので、h1 の上に、本文と同じ幅（720px）・16:9 の静止画を 1 枚足す形に型を変える（★）。`01-content-spec.md` §4.11 にその旨を書き足す。規約・ポリシー（C の区分）の型は変えない。

## 8. 実績の展示の壁（A-16）

- 額は 2 種類を混ぜて並べる（★）:
  - **このサイトの実績**（いま掛けるもの）。候補（★。中身と言い回しはユーザーの確認を通す）:
    - この体験そのもの（Astro・React・Three.js で作ったアトリエ）
    - JIS X 8341-3 の AA に一部準拠し、試験結果を公開している（移り先 `/accessibility/`）
    - Lighthouse の SEO 1.0・accessibility 1.0（数値は、確認の時点で実際に計った値だけを書く）
    - 運用を回すエージェントの基盤（再帰的自己改善）。**Tips を持たない飾りの額**にする（★。説明のあるページは環境構築のワークステーションと同じ移り先になり、壁の前から移ったのにワークステーションの絵が出る＝アンチゴール 1・2 に当たるため）
  - **他社の実績**: `cases.ts` の `publishedCases()` が返す件だけ（掲載許可が `granted`）。いまは 0 件なので掛からない。
- 額の Tips を押した移り先は、その実績を裏付けるページだけにする（★）。裏付けるページが無い実績の額は Tips を持たない飾りにするか、掛けない（押しても行き先の無い Tips を作らない）。
- 他社の実績の移り先は、トップの 1-8 導入事例の節（★。外部のサイトへ直接は飛ばさない）。
- 許可が取れたら `cases.ts` の `permission` を `granted` にするだけで額が増える（★）。額の数が変わっても壁の構図が崩れないよう、額の枠は最大数（自社の実績＋3 社）を先に置き、空きは無地の額にする（★）。

## 9. シームレスの約束（★）

アンチゴール 2 に対する作り方の約束。第 1 版の §9 を引き継ぎ、一人称に合わせて足した。

1. **ポスター・静止画と立体を同じ絵にする。** ポスターと下層ページの静止画は、実行時と同じシーン・同じカメラ・同じ光・同じ時間帯で、three 自身に描かせて書き出す（Blender の別のレンダラーで描かない）。
2. **読み込み中に白い枠を出さない。** ヒーローの大きさは CSS で先に確保する（CLS 0）。ポスターは `fetchpriority="high"`。
3. **Tips → 下層ページを、カメラの移動としてつなぐ。** Tips を押すと、カメラが移り先の静止画と同じ位置・角度へ動き（`--motion-duration-*`・`--motion-ease-*` のトークン）、その最後のフレームと、移り先の冒頭の静止画を、文書間の View Transitions でつなぐ。移り先の冒頭の画像の大きさへ縮む形の移り方（第 1 版の `vt-diorama` と同じく、名前は遷移の間だけ付ける）。
4. **どの状態でも同じアトリエに見える。** reduced-motion・JS なし・WebGL なし・一時停止は、すべて同じポスター（動かないだけ）。
5. **時間帯をそろえる。** 1 回の訪問の中では、トップと下層ページで同じ時間帯の絵を出す（開いた時の時間帯を `sessionStorage` に残す。★）。

## 10. 性能の予算（★）

| 項目 | 予算 |
|---|---|
| 最初の描画 | 文字（HTML）と、スタート地点のポスター（その時間帯。WebP。Desktop 200KB・Mobile 120KB 以内）だけ。three は読まない |
| three とアトリエの読み込み | 既存の `loadThree()`。ページの `load` の後の idle で読み始める |
| アトリエの glb | meshopt 圧縮、テクスチャは WebP（第 1 版と同じ。新しい依存を足さない）。**3MB 以内**。家具は面を減らし、AO と素材の色を焼き込む。Mobile は解像度の低いテクスチャの組（1.5MB 以内）を別に持つ |
| 空 | 時間帯ごとの HDRI は、その時間帯の 1 本だけを読む（各 300KB 以内）。夜の星は three で描く |
| アバター | 既存の `avatar.vrm`（4.3MB）と身ぶりのクリップ。アトリエの後に読む |
| 描画 | 室内の光は時間帯ごとの実時間の光（焼き込みは AO と素材の色だけ。4 つの時間帯ぶんの光を焼くと glb が 4 倍になるため）。Desktop の描画解像度は最大 2 倍、Mobile は最大 1.5 倍。画面外・タブ非表示では rAF を止める |
| 遅い端末 | 第 1 版の `decideQuality`（中央値）で判定し、遅ければ解像度を下げ、それでも遅ければポスターと一覧（§6.5） |
| Lighthouse | accessibility 1.0、SEO 1.0 を保つ。performance は ADR-29 のとおり warn |

## 11. 端のアバターを外す（A-13）

- `BaseLayout.astro` から `AvatarDock` を外し、サイト全体で画面の端にアバターを出さない。
- `avatar` モジュールは、アトリエの中のアバターが使う部分（VRM と身ぶりのクリップの読み込み・`lib/figure.ts`・資産）だけを残す（★）。端のアバターにしか使わない部分（`AvatarDock`・`AvatarStage`・端に出す／引っ込める判定〈`yield.ts`・`scroll-away.ts`〉・スクロールで身ぶりをする仕組み〈R20 の triggers・emotes〉）は消す（★）。
  - 消す部分の単体テスト・e2e（`avatar.spec.ts` のうち端のアバターを見るもの）も一緒に消す。作業前から落ちている R20 のテスト（単体 24 件の一部と a11y の 2 件）は、この削除で無くなるものがある。その数を最終報告に書く。
- 静止画の中にアバターが写るのは、会社概要の冒頭（表札の奥に立つアバター）（★。「同じ人がいる」ことを下層ページでも保つ）。
